# Контракт для бэкендера: порядок вопросов и ответы на публичную форму

Фронтенд реализован. Методы ниже — **предлагаемый контракт новых API**, а не уже
существующие маршруты бэкенда. Backend в этой задаче не изменён.
Все поля JSON — camelCase. Базовый адрес берётся из `VITE_API_URL` (по умолчанию `/api`).
Фронтенд добавляет пути ниже к этому адресу; второй `/api` добавлять не нужно.

## 1. Сохранение порядка вопросов

`PATCH /api/forms/{formId}/questions/order`

Авторизация: `Authorization: Bearer <accessToken>`, только владелец формы.
Тело содержит **все** ID текущих вопросов в новом порядке:

```json
{ "questionIds": ["question-2", "question-1", "question-3"] }
```

ID в примерах условные; реальные ID формы, вопросов и вариантов — строки (в том числе UUID).
Нужно проверить принадлежность вопросов форме, отсутствие пропусков, дубликатов
и лишних ID. Сохранить весь порядок атомарно, назначив `sortOrder` от 0.

Ответ `200`:

```json
{
  "questions": [
    {
      "id": "question-2", "text": "Ваш возраст?", "type": "number",
      "isRequired": true, "sortOrder": 0, "options": []
    },
    {
      "id": "question-1", "text": "Ваш отзыв?", "type": "short_text",
      "isRequired": true, "sortOrder": 1, "options": []
    },
    {
      "id": "question-3", "text": "Какой формат удобнее?", "type": "single_choice",
      "isRequired": false, "sortOrder": 2,
      "options": [
        { "id": "option-1", "text": "Онлайн", "sortOrder": 0 },
        { "id": "option-2", "text": "Очно", "sortOrder": 1 }
      ]
    }
  ]
}
```

При перетаскивании фронтенд показывает предварительный порядок и отправляет
запрос один раз после отпускания. Esc отменяет перемещение. При сбое
восстанавливается прежний порядок. Кнопки меняют порядок после подтверждения
API. `401` — требуется вход; `403` — чужая форма;
`404` — нет формы; `409` — список вопросов изменился или форма закрыта.

## 2. Получение формы для участника

Страница сайта: `/f/{formId}`. Без входа и панели владельца.

`GET /api/public/forms/{formId}` — **без авторизации**.
Возвращать только опубликованную форму и её вопросы. Не возвращать данные
владельца, токены и ранее отправленные ответы.

Ответ `200`:

```json
{
  "id": "form-1",
  "title": "Обратная связь",
  "description": "Поделитесь впечатлениями",
  "status": "published",
  "questions": [
    {
      "id": "question-1", "text": "Ваш отзыв?", "type": "short_text",
      "isRequired": true, "sortOrder": 0, "options": []
    },
    {
      "id": "question-2", "text": "Оценка", "type": "number",
      "isRequired": true, "sortOrder": 1, "options": []
    },
    {
      "id": "question-3", "text": "Формат", "type": "single_choice",
      "isRequired": true, "sortOrder": 2,
      "options": [
        { "id": "option-1", "text": "Онлайн", "sortOrder": 0 },
        { "id": "option-2", "text": "Очно", "sortOrder": 1 }
      ]
    },
    {
      "id": "question-4", "text": "Темы", "type": "multiple_choice",
      "isRequired": false, "sortOrder": 3,
      "options": [
        { "id": "option-3", "text": "React", "sortOrder": 0 },
        { "id": "option-4", "text": "API", "sortOrder": 1 }
      ]
    }
  ]
}
```

`404` — форма не существует или не опубликована; `410` — приём ответов закрыт.
Порядок вопросов и вариантов определяется полем `sortOrder`.

## 3. Отправка ответов

`POST /api/public/forms/{formId}/responses` — **без авторизации**.

```json
{
  "submissionId": "1b504e0e-727d-4e75-8d5a-826b1df93618",
  "answers": [
    { "questionId": "question-1", "value": "Всё понятно" },
    { "questionId": "question-2", "value": 4.5 },
    { "questionId": "question-3", "value": "option-1" },
    { "questionId": "question-4", "value": ["option-3", "option-4"] }
  ]
}
```

Тип `value` зависит от вопроса:

- `short_text`: непустая строка после trim;
- `number`: конечное JSON-число (0 — допустимый ответ);
- `single_choice`: строковый ID одного варианта;
- `multiple_choice`: массив уникальных ID вариантов.

Незаполненные необязательные вопросы не включаются в `answers`.
Проверять на сервере статус формы, обязательные вопросы, типы значений,
принадлежность questionId и optionId, отсутствие дубликатов и неизвестных ID.
Сохранять одну отправку и все её ответы транзакционно; обновить `responsesCount`
в списке владельца. Фронтенд не заменяет серверную валидацию.

`submissionId` генерируется фронтендом один раз для попытки и сохраняется при
повторе запроса после ошибки/таймаута без изменения ответов. Сервер должен
обеспечить уникальность `(formId, submissionId)` и идемпотентность: повтор
того же тела возвращает исходную квитанцию, не создавая второй ответ.
Тот же ID с другим телом — `409`. Правка ответа на фронтенде создаёт новую попытку.

Ответ `201` (либо `200` для повторного запроса):

```json
{
  "responseId": "response-uuid",
  "submittedAt": "2026-11-18T12:00:00Z"
}
```

Успех показывается только после получения валидной квитанции. При ошибке
введённые ответы остаются в полях. `400`/`422` — невалидные ответы;
`404` — нет публичной формы; `409` — конфликт; `410` — закрыта; `429` — лимит;
`5xx` — ошибка сервера. Публичный клиент не отправляет JWT и не выполняет refresh
или редирект на `/login` при ошибке доступа.

## Что ещё требуется в текущем бэкенде

Для полного пути обычного аккаунта нужны уже ожидаемые фронтендом методы:

- `GET /api/forms` — список форм владельца с `responsesCount`;
- `POST /api/forms/{id}/publish` — публикация, ответ с актуальными данными формы.

В текущем checkout этих маршрутов нет. Документ не подтверждает их готовность.
После реализации согласуйте URL/JSON со Swagger. Если контракт другой,
адаптация выполняется в `src/api/formsClient.ts` и `src/api/publicFormsClient.ts`.
Для отправки ссылки с другого устройства нужен доступный ему адрес сайта
и сервера; `127.0.0.1` обозначает текущее устройство.

## Как проверить фронтенд до готовности API

1. `npm run dev`, вход `admin@example.com` / `password123`.
2. «Мои формы» → «Подробнее» → добавить несколько вопросов.
3. Перетаскивание за значок ⠿ и «Выше / Ниже» меняют порядок и сохраняют его. Первая кнопка «Выше»
   и последняя «Ниже» отключены. Обновление страницы сохраняет порядок.
4. Опубликовать форму → «Открыть как участник». Тестовая ссылка имеет вид
   `/f/{id}?demo=1`, работает без входа, но только в том же браузере и origin.
5. Пустые обязательные поля блокируют отправку. После заполнения →
   «Отправить ответы» → подтверждение. В «Моих формах» увеличивается счётчик.

Тестовые формы и ответы хранятся в localStorage под ключом
`form-builder:demo-forms:v1` (поля `forms`, `responses`). Это демонстрация,
а не серверное хранение. Ошибки настоящего API никогда не включают демо.
Демо доступно только в режиме разработки.

Автотесты: `npm test`. Проверки типов, сборки и стиля:
`npx tsc --noEmit`, `npm run build`, `npm run lint`.
